## 2024-10-24 - Pass optional file paths to functions to avoid subshell capture overhead
**Learning:** In `lxc-cleanup.sh`, a function outputting structured metadata (like `RAW_FREED_KB:<value>`) directly to stdout forces the caller to capture the entire stream in a subshell (`result=$(func)`). The caller then has to parse the metadata out and strip it using expensive string manipulation before writing the rest of the stream. This double-handling of data causes immense performance bottlenecks in large batch processing loops.
**Action:** When a function needs to return side-channel data alongside standard output text, pass the target output directory or file path as an optional argument to the function. This allows the function to write the metadata directly to disk and allows the caller to stream the main output cleanly, entirely bypassing the subshell process fork and string manipulation overhead.
